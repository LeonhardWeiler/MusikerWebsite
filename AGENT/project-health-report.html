Open findings

high A11Y-1 — The "More" trigger cannot be operated by keyboard

index.html:47 and index.html:147 · js/script.js

The dialog is opened by <a class="link__more-a" id="beatles__open">More</a>. An <a> without an href is not focusable and exposes no button role, so keyboard and assistive-technology users cannot reach or activate it. Opening the biography dialog is a core flow of the page, and it is unavailable without a mouse.

Recommendation: Use a real <button type="button"> for the trigger (keep the existing IDs and click handlers). It is focusable, activates on Enter/Space and announces as a button.

medium BUG-1 — The "SF-Pro_Regular" font face loads the Semibold file

css/style.css:19

The @font-face named SF-Pro_Regular sets its src to ../assets/fonts/SF-Pro_Semibold.woff2, even though SF-Pro_Regular.woff2 exists in the same folder. Body text (which uses font-family: "SF-Pro_Regular") is therefore rendered with the Semibold weight rather than the intended regular weight.

Recommendation: Point the SF-Pro_Regular face at ../assets/fonts/SF-Pro_Regular.woff2.

medium CQ-1 — Per-artist dialog wiring is duplicated

js/script.js:3-23

The open/close logic is copy-pasted once per artist (Beatles, Bob Dylan). Each new artist requires another near-identical block, and the markup/JS must be kept in sync by hand — an easy source of mismatched-ID bugs.

Recommendation: Derive the behaviour from the markup, e.g. iterate over all .link__more-a triggers (or query each section's dialog/close button by a shared data attribute) and attach the handlers in a loop.

low SEC-1 — External links open in a new tab without rel="noopener"

index.html — all target="_blank" anchors

The Instagram/YouTube/Spotify links use target="_blank" without rel="noopener noreferrer". Modern browsers imply noopener for _blank, but adding it explicitly protects older browsers from reverse tabnabbing and documents the intent.

Recommendation: Add rel="noopener noreferrer" to every target="_blank" link.

low A11Y-2 — Hidden scrollbars plus mandatory scroll-snap reduce discoverability

css/style.css:32-34 (::-webkit-scrollbar { display: none }), css/style.css:65 (scroll-snap-type: block mandatory)

Scrollbars are hidden globally while sections use mandatory full-height snap. On desktop there is little visible affordance that a second artist section exists below the fold, and the missing scrollbar removes the usual position cue.

Recommendation: Consider keeping a subtle scroll indicator, or a visible cue between sections, so users know there is more to scroll to.

low CQ-2 — Minor JavaScript style inconsistencies

js/script.js:13-15

Assignments such as const bobdylanOpen= document.getElementById(...) miss the space before =, and the two artist blocks are formatted slightly differently. Purely cosmetic, but it stands out in a tiny file.

Recommendation: Normalise spacing (and ideally fold this into the CQ-1 refactor). A formatter such as Prettier would keep it consistent automatically.

info INFO-1 — No automated checks; content depends on external image URLs

repository-wide · index.html (i.scdn.co image sources)

There is no lint/test/build step (reasonable for a page this size). Separately, hero, dialog and album images are hot-linked from Spotify's CDN (i.scdn.co); if those URLs change or expire the images silently break.

Recommendation: Optional — add a lightweight HTML/CSS linter or link checker in CI, and consider self-hosting critical images to remove the external dependency.

What is already strong

  • Clean semantic structure: <section> with aria-label, <nav>/<ul> link bars, and headings in order.
  • Uses the native <dialog> element with showModal() — free focus trapping and Escape-to-close.
  • Decorative SVGs are marked aria-hidden="true"; the close icon has a <title>; images carry descriptive alt text.
  • Styling is well organised around CSS custom properties (colours, font sizes, spacing) and uses clamp() for fluid typography.
  • Responsive: the dialog grid gracefully collapses to a column on narrow screens.
  • Zero dependencies and no build step — trivial to deploy and maintain.
  • Now documented: README.md, CLAUDE.md and CHANGELOG.md, with SPDX-License-Identifier headers on source files.

Deliberate decisions (not findings)

  • No framework / no build system. Plain HTML/CSS/JS served by GitHub Pages from the repo root is an intentional simplicity choice for a small showcase.
  • External CDN images. Album and artist art is intentionally hot-linked from Spotify rather than bundled (tracked as a fragility note in INFO-1).
